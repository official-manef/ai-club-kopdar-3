Target Akhir

Yang harus tercapai malam ini

  • Instance Hermes sendiri dan model AI aktif.
  • Workspace Repliz sendiri dengan akun Threads berstatus Connected.
  • Skill kustom /repliz yang menggunakan Repliz REST API.
  • Access Key dan Secret Key tersimpan aman di Environment / .env.
  • Satu konten personal branding yang dijadwalkan dan diverifikasi di Threads.

Tiga aturan yang tidak bisa ditawar

Wajib dipatuhi

3. Satu-satunya persetujuan posting yang valid adalah teks persis: SETUJU POST

1
Membuat Hermes dan Menghubungkan ModelBuat instance, ikuti setup wizard, lalu aktifkan model AI
  1. Buka https://gethermes.cloud/ dan login atau buat akun.
  2. Buat instance baru, tentukan display name dan slug, lalu tunggu provisioning selesai.
  3. Buka URL instance dan selesaikan setup wizard.
  4. Di menu KEY, hubungkan model melalui opsi yang tersedia pada Hermes — misalnya OAuth atau custom LLM.
  5. Pilih model utama dan simpan pengaturan.
Catatan provider

Nama menu dapat berbeda menurut versi instance. Ikuti setup wizard dan gunakan opsi provider yang tersedia. API key provider tidak boleh dikirim melalui chat.

Beritahu saya:
1. Apakah model AI sudah aktif
2. Nama model yang sedang digunakan
3. Apakah kamu siap menerima instruksi

Jangan tampilkan API key atau credential apa pun.
OKHermes dapat menjawab dan menyebutkan model yang sedang digunakan.
2
Membuat Repliz dan Menghubungkan ThreadsGunakan workspace masing-masing peserta

Buat akun Repliz melalui: https://repliz.com/referral/6RZ23S

  1. Daftar menggunakan email, login ke dashboard, dan pastikan berada di workspace sendiri.
  2. Periksa paket yang digunakan. Daftar akun API memerlukan Standard+, sedangkan Schedule API memerlukan Premium+.
  3. Buka Account Integration, pilih Integration, cari Threads, lalu klik Connect.
  4. Login ke Threads, berikan permission yang diminta, lalu kembali ke Repliz.
Kenapa koneksi dilakukan di dashboard?

Koneksi akun Threads menggunakan proses OAuth interaktif di browser. Lakukan langkah ini langsung melalui dashboard Repliz, bukan melalui skill.

3
Membuat dan Menyimpan API KeyCredential disimpan di Environment, bukan di chat
  1. Di Repliz, buka Settings → Public API atau API.
  2. Klik Generate New Keys untuk mendapatkan Access Key dan Secret Key.
  3. Di dashboard Hermes, buka API Keys atau Environment.
  4. Tambahkan REPLIZ_ACCESS_KEY dan REPLIZ_SECRET_KEY, lalu klik Save.
  5. Pastikan nilainya ditampilkan dalam bentuk tersamarkan.
  6. Buka sesi chat baru agar environment terbaru terbaca.
Wajib

Jangan menempelkan key ke chat Hermes, ChatGPT, WhatsApp, dokumen bersama, screenshot, source code, atau SKILL.md. Hermes menyimpan secret pengguna di ~/.hermes/.env melalui dashboard API Keys / Environment.

Nama Environment VariableMasukkan nilainya di dashboard, bukan di chat
REPLIZ_ACCESS_KEY
REPLIZ_SECRET_KEY
OKKedua environment variable sudah tersimpan dan tersamarkan.
4
Membuat Skill Kustom ReplizSkill memakai REST API resmi Repliz dan tidak menggunakan MCP
Penting

Skill ini adalah skill kustom yang dibuat pada instance Hermes peserta. Dasarnya adalah dokumentasi REST API resmi Repliz. Workshop ini tidak memasang Repliz MCP.

Prompt Utama — Buat SkillSalin seluruh blok ke chat Hermes
Buat Hermes Skill kustom bernama "repliz".

Sumber resmi: https://docs.repliz.com/

Ketentuan:
1. Gunakan Hermes Skill, bukan MCP.
2. Simpan sebagai ~/.hermes/skills/repliz/SKILL.md.
3. Buat scripts/repliz.py menggunakan Python 3 standard library saja.
4. Base URL: https://api.repliz.com
5. Gunakan HTTP Basic Authentication.
6. Baca credential hanya dari:
   - REPLIZ_ACCESS_KEY
   - REPLIZ_SECRET_KEY
7. Deklarasikan keduanya di frontmatter required_environment_variables
   dengan field name, prompt, help, dan required_for.
8. Jangan menyimpan atau mencetak credential di file, output, atau log.

Script minimal harus mendukung:
- list-accounts: GET /public/account, filter types[0]=threads
- list-schedules: GET /public/schedule
- get-schedule: mengambil satu schedule berdasarkan ID
- create-schedule: POST /public/schedule

Payload posting teks:
- title: ""
- description: isi posting
- type: "text"
- medias: []
- accountId: ID akun Threads
- scheduleAt: waktu ISO 8601

Aturan keamanan write action:
- GET boleh berjalan tanpa persetujuan.
- Sebelum POST, tampilkan preview username, Account ID, isi,
  jumlah karakter, dan waktu ISO 8601.
- Jangan POST sebelum pengguna mengetik persis: SETUJU POST
- Script create-schedule harus menolak eksekusi kecuali menerima
  argumen --confirm "SETUJU POST".
- Jangan membuat schedule saat instalasi.

Setelah selesai:
1. Validasi SKILL.md dan script.
2. Pastikan tidak ada credential di source code.
3. Pastikan write action memiliki confirmation gate.
4. Jangan melakukan request POST.
5. Tampilkan status pemasangan dan langkah berikutnya.
Jika perubahan berstatus pending

Apabila skills.write_approval aktif, buka halaman Skills dan approve perubahan. Alternatif perintah: /skills pending, /skills diff <id>, lalu /skills approve <id>.

Muat Ulang Daftar SkillAtau buka sesi baru

Troubleshooting SingkatMasalah yang paling mungkin muncul dan tindakannya

  

    

      
MasalahTindakan

      
        
/repliz tidak munculJalankan /reload-skills atau buka sesi baru. Periksa halaman Skills dan approval pending.

        
Key tidak terdeteksiPeriksa nama REPLIZ_ACCESS_KEY dan REPLIZ_SECRET_KEY, hapus spasi, Save, lalu buka sesi baru.

        
401 UnauthorizedSalin ulang key dari workspace yang benar. Jangan pernah mengirim nilainya ke chat.

        
Akun Threads tidak munculBuka Account Integration di Repliz, lalu reconnect dan setujui permission.

        
Schedule API ditolakPastikan paket Repliz adalah Premium+ dan waktu scheduleAt valid ISO 8601.

        
Schedule berstatus errorMinta detail secara read-only. Jangan retry sebelum penyebab dipahami dan disetujui.

      
    

  


  

    
Diagnosis Schedule ErrorRead-only, tanpa retry


/repliz

Periksa detail schedule terakhir secara read-only.
Tampilkan status dan pesan error.

Jangan melakukan retry.
Jangan membuat schedule baru.
Jangan mengubah atau menghapus data.
